# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A collection of PyTorch tutorial samples presented as Jupyter notebooks. Notebook prose (markdown cells) is written in Korean. See `README.md` for the section index.

## Layout rules (user requirements)

- **One notebook per section.** Each section lives in its own folder `NN_<topic>/` containing exactly `NN_<topic>.ipynb`. When adding a section, use the next number and add it to the table in `README.md`.
- **Per-section data folder.** All data a section uses lives in that section's `data/` and is referenced by the relative path `data/`. Sections never read another section's data, so each runs standalone.
  - Small synthetic datasets are generated by the notebook if missing (`if not path.exists(): ...`) and committed.
  - Large downloads go to `data/downloads/`, and trained weights to `data/*.pt`. Both are gitignored.
  - Sections whose `data/` would otherwise be empty or fully gitignored keep a `data/.gitkeep`.

## Notebook conventions

- Cell order: title + 학습 목표 (markdown) → setup cell → numbered `## N.` sections → `## 요약`.
- The setup cell sets `torch.manual_seed(42)` and `device = "cuda" if torch.cuda.is_available() else "cpu"`. Tensors and models go through `.to(device)`.
- Keep training short enough to finish on CPU in a few minutes (small epoch counts, subsets).
- Notebooks are committed **with executed outputs**, because they are meant to be read as rendered samples. Re-execute after editing.

## Commands

```bash
pip install -r requirements.txt

# Execute one notebook in place (nbconvert runs it with the notebook's folder as cwd)
jupyter nbconvert --to notebook --execute --inplace 03_linear_regression/03_linear_regression.ipynb

# Execute all notebooks
jupyter nbconvert --to notebook --execute --inplace [0-9][0-9]_*/*.ipynb
```

There is no test suite or linter. A notebook "passes" if it executes without errors.

Sections 05 and 06 download MNIST and FashionMNIST, which are reachable from Claude Code cloud sessions. `download.pytorch.org` (CPU wheels, pretrained weights), HuggingFace and CIFAR-10's host are blocked there. That is why 06 pretrains its own source model instead of using ImageNet weights, and why torch is installed from conda-forge instead (PyPI's CUDA build is very slow to download):

```bash
curl -sSL https://conda.anaconda.org/conda-forge/linux-64/micromamba-2.0.5-0.tar.bz2 | tar xj bin/micromamba
MAMBA_ROOT_PREFIX=~/mamba bin/micromamba create -y -p ~/condaenv -c conda-forge python=3.12 "pytorch=*=cpu*" torchvision matplotlib pandas nbconvert ipykernel
export PATH=~/condaenv/bin:$PATH
```

On a section's first run, dataset download progress is printed into the notebook output. Execute it a second time (data is then cached) before committing, so the saved outputs stay clean.
